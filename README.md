＜学食混雑緩和アプリ＞
ターゲット：
急いで昼食をとりたい人

ゴール：
学食の列を分散させること

アプリの使用：
アプリの利用者があと何分で昼食を済ませたいかを入力する→アプリ内で時間内に済む選択肢のみを提示する。ただ時間を伝えるのではなく提示をする形で意思決定をしてもらう。

明治大学の学食について：
食券を購入した後３列に並ぶ。「カレーとうどん」「からあげ丼と日替わり定食」「ラーメンと混ぜそば」この３つである

なぜ混むのか？(原因についての考察)：
４月から週２回以上学食を利用し、感じたことを基に考察を行った。
まず、お金がかかる部分(調理室が狭い、人数が少ない)が原因ではないと考える。
なぜなら２限終わり(一番混雑する時間)から３０分もすればどの列も空いているから。
ここで２つの原因があると考えた。
１つ目はピーク時(２限終わり)に人が押し寄せることだと考える。
２つ目は商品の人気度に差があることだと考える。
事実として「カレーとうどん」の列は時間関係なくいつも空いているからである。
２つ原因を上げたが本質的には１つだと思っている。
「人が押し寄せる」→混む　ではなく、「商品の人気度に差がある」→混んでいるように見えるのだと考える。
なぜなら、先ほども述べたように、ピーク時であっても素早く昼食をとる方法は存在するからである。
以上のことを踏まえ、「商品の人気度に差があること」を原因として考え、列の分散をゴールにアプリ開発に取り組んだ。

あえてやらなかったこと：
時間軸での問題解決→原因の追究でも述べた通り、本質の原因ではないと考えたため。また時間割を変更するなどは不可能であるため。
予約のシステム→学食の席は「誰でも使え、いつでも使え、自由に利用していい場所」である。予約システムが導入されるとこの場所が学生にとって使いにくくなってしまうと考えたので導入しなかった。また、アプリが複雑になるため導入しなかった。
カメラ、センサーを利用したリアルタイム機能→導入に時間、お金が莫大にかかる。

工夫した点：
このアプリではデータ収集を通じて「この時間帯から並んだら、このくらいかかる」といった基本のデータをまず用意しておく。
だが、このアプリを使用することでいつも空いてる「うどんとカレー」の列に並ぶ人が増え、基本のデータ通りにいかないことが予想される。
そのため、リアルタイムでかかる時間を変更する機能を導入する。
リアルタイム機能といってもシンプルである。
アプリの利用者がx列(ｘは１か２か３)を選択したらx列の並ぶ時間は「基本のデータの時間＋４５秒(４５秒は仮)×選択人数」とリアルタイムで変化する。
ただし、このままだと並ぶ時間が永遠に増え続けるので、１分(仮)たったら選択人数は１人減る仕組みにする。
その結果、全部の列が混むことも考えられる。
そうしたら、学食で急ぐことは不可能なので、「コンビニで済ませる」という選択肢を表示する。
ここで、みんながみんなわざわざこのアプリを利用して、選択をするのだろうか？と考えた。
しかし、全部のデータがなかったとしても一部のデータがあれば動きとしては予測することは可能であると考えるため問題はないと考える。
